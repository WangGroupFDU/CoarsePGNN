# PU 反向设计：准备层与接续协议

## 当前状态

本研究分支实现数据审计、固定分组划分、原料规格与配比转换、请求校验，以及性质集合编码—D/P/E 自回归选择—连续配比 MDN 的神经网络核心。**尚未训练完整反向模型，尚无可用模型权重，也没有 GPT PASS。** `propose()` 只返回待前向核验的提案，不能解释为合成成功或实验达标。

用户批准的范围为线型双官能 PU：一种二异氰酸酯 D、一种宏二醇 P、可选一种二醇扩链剂 E；目标为 Tg、Tm、极限拉伸强度和断裂伸长率。验收使用计算与已有实测数据，不要求新增合成实验。预算为最多 10 个正式研究轮次或累计 72 小时计算墙钟时间，先到即止。工程预检独立记录，不计作正式训练轮次。

原讨论会话为 [文献调研聚合物反向设计](https://chatgpt.com/c/6af063c3-b6c0-83ea-834e-9a52ab4df547)。必须由该会话根据审计证据先确定量化成功标准，再冻结训练、基线和评估协议。不能用本文件中的建议替代该裁决。

## 数据依据与限制

`configs/inverse/pu_20261111_sources.json` 固定四个修正后的任务行文件和 SQLite 数据库 SHA-256。原文件只读，派生审计写入新目录。共 3657 条观察、1162 个材料、202 个来源；每张原始图重新核验文件散列，并由当前公开 featurizer 重算完整图张量散列。

材料、配方、实际图张量及文献来源四种身份取传递闭包，得到 185 个关联组。固定 seed=20261111，按观察数量和任务覆盖尽量接近 64/16/20 分配；不使用性质数值或模型表现选种子。标签变换、条件编码器和监督前向模型只能在训练部分拟合，旧权重须先证明未接触新留出集，否则重训。

初步得到 945 个模板与质量字段完整的材料：184 个材料不符合模板，32 个缺少宏二醇 Mn，1 个缺少小分子摩尔质量。规格库按角色、结构、质量和表示层级区分，共 29 个 D、155 个 P、74 个 E；这些数量不是独立实验样本量。来源结构仍需化学资格核查，不从 PSMILES 星号推断端羟基。

246 条 Tg 是整理流程的跨测量均值，其中存在跨测量定义、方法或扫描条件的合并。审计将其标为 `derived_cross_measurement_mean`，保留原来源和成员数，不能直接以被保留的某一个 protocol 监督条件模型。论文原本报告的重复实验均值不由此规则排除。是否恢复原子测量、作为单独任务或排除，由原会话在训练前裁决。

同材料具有四项性质的有 246 个，但按已有 specimen_id 关联的四性质候选只有 48 组，且**尚未核准制备状态、热历史与定义的兼容性**。不得将材料 ID 的多性质并集当作同一状态联合实测。`joint_candidates.csv` 全部保持待语义核准。缺失标签不补齐；标签掩码、请求目标掩码和条件缺失掩码必须分开。

验证和测试分别有 82、69 个材料含训练中未见规格。冻结协议必须明确结构特征可用于何种已知库/未见规格设置，单列这部分结果，不能在训练结束后删去困难样本。

## 已实现的数学表示

所有反应组分官能度为二时，以 OH 总量归一化：

```text
R = n(D) / [n(P) + n(E)] = NCO/OH
v = n(E) / [n(P) + n(E)]
D:P:E = R:(1-v):v
w(i) = n(i) M(i) / sum_j[n(j) M(j)]
```

历史 R 保留原值；E=NONE 时 v 必须严格为零。宏二醇质量使用来源 Mn。质量分数仅指反应原料，不含未建模的催化剂或溶剂。

`InverseDesigner` 将每条性质请求的性质嵌入 16 维、区间 2 维、边界掩码 2 维、外部 Test Encoder 输出 48 维和 assay 表征 16 维拼成 84 维，编码并集合汇聚。GRU 按 D→P→E/NONE 选择规格；MDN 在最终 D/P/E 全部确定后输出三分量 `z=logit(v)` 分布。监督损失为逐样本原料交叉熵加 z 空间负对数似然，供训练器实施材料等权。MDN 权重和生成概率不是性质达标概率。

目前未实现：真实特征/条件编码器接线、训练器与检查点、前向评估器适配、候选构图、完整 `design/evaluate` 命令、基线与最终统计评估。因此不能把核心模块测试通过表述为完整模型训练成功。

使用 cn2 现有 Anaconda base，不安装包。源码需已提交且工作区干净：

```bash
export PYTHONPATH="$PWD/src"
/opt/anaconda2023/bin/python -m unittest discover -s tests -p test_inverse.py -v
/opt/anaconda2023/bin/python -m coarsepgnn_inverse validate-request --input examples/inverse/request.json
/opt/anaconda2023/bin/python -m coarsepgnn_inverse stoichiometry --input examples/inverse/stoichiometry.json --output /tmp/pu_ratio_new.json
```

`request.json` 是输入格式示例，不是已冻结的实验目标或经过校准的默认协议。输出存在时明确报错，避免覆盖旧回执。所有数据 CSV 为 UTF-8 BOM、逗号分隔、CRLF。

## 接续顺序

1. 原会话确认派生标签、联合监督、端点定义与候选库的使用规则；定量冻结成功标准、容差、分母、置信区间、失败条件与一次性测试打开规则。
2. 按固定划分接线现有前向框架和 Test Encoder，完成来源与权重兼容性检查。只用验证集选择超参数。
3. 实现并训练生成器；同等前向调用预算比较检索、合法随机和组合/配比搜索基线。完成必要消融，最终使用三随机种子。
4. 迭代仅使用验证证据；冻结版本后打开测试。分开报告代理筛选命中、独立实测锚点验证、分布外样本及合成依据。不能将前向模型自评视为独立实验确认。
5. 每轮保留真实代码、输入、参数、环境、回执、指标和失败；通过 GitHub 证据提交供原会话评审。只有真实版本对应的 PASS 和全部验收通过，才结束研究。
